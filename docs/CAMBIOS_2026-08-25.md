# Cambios — 25/08/2026 — Módulo Actuarial: 6 fases de mejora

Registro de los cambios realizados el día 25/08/2026 sobre la rama `feature/cuadratica/actuarial`.

## Objetivo

Mejorar el módulo actuarial en 6 fases: reducir el límite de N, agregar procesamiento asíncrono por lotes,
habilitar el coeficiente B estocástico, mejorar las etiquetas de la interfaz, ejecutar Monte Carlo
localmente en el navegador, hacer el gráfico responsive y persistir las simulaciones vinculadas a Leads.

## Fase 1.1 — Reducir límite de N a 25.000

### Cambios

- `packages/shared/src/dtos/actuarial.ts` — `.max(25000)` en `nSimulaciones` (era 100.000).
- `apps/frontend/src/app/features/actuarial/actuarial.component.html` — label "25.000" en el slider.
- `apps/backend/bench/actuarial.bench.ts` — benchmarks actualizados a 25.000.
- `apps/backend/bench/concurrencia.bench.ts` — `N = 25000` (era 100.000).
- Tests: actualizados todos los fixtures con `nSimulaciones` y los tests de rechazo.

### Decisión

25.000 iteraciones ofrecen convergencia suficiente para decisiones de pricing y mantienen
el bloqueo del event loop por debajo de ~400 ms en hardware estándar.

## Fase 1.2 — `simularRiesgoAsync` con chunking

### Cambios

- `packages/shared/src/dominio/actuarial/monteCarlo.ts`:
  - `TAMANO_LOTE = 5000` — cada 5.000 iteraciones se cede el control al event loop.
  - `cederAlEventLoop()` — `new Promise(r => setTimeout(r, 0))`.
  - `ejecutarIteracion()` — función extraída del loop para modularidad.
  - `construirResultado()` — función extraída que arma la respuesta.
  - `simularRiesgoAsync()` — nueva función async, idéntica a `simularRiesgo` pero con `await cederAlEventLoop()` entre lotes.
  - `simularRiesgo()` — preservada intacta para tests síncronos.

### Decisión

Se mantiene la versión síncrona porque los tests unitarios no necesitan async. La versión
async se usa en producción (backend y frontend) para no bloquear el event loop.

el backend. El servicio HTTP se mantiene como fallback opcional.
