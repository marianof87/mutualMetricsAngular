## 1. Problema detectado (duplicación)

La auditoría de QA detectó que la política de "sesión/token rechazado" estaba
**duplicada** en dos lugares del frontend, con el mismo valor semántico pero nombres
distintos:

| Archivo | Constante local | Uso |
|---|---|---|
| `apps/frontend/src/app/core/interceptores/errores.interceptor.ts` | `CODIGOS_SESION_INVALIDA` | Redirige a `/login` y limpia sesión |
| `apps/frontend/src/app/core/servicios/sesion.service.ts` | `CODIGOS_TOKEN_RECHAZADO` | `revalidar()` decide desloguear |

Ambas listaban `[AUTH_TOKEN_EXPIRADO, AUTH_TOKEN_INVALIDO]`. Esta duplicación implicaba
riesgo de **deriva**: si mañana cambia la política (p. ej. agregar
`AUTH_CREDENCIALES_INVALIDAS` o quitar un código), hay que recordar actualizar **dos**
sitios o la lógica de sesión queda inconsistente.

## 3. Ciclo TDD — Fase GREEN (centralización en `packages/shared`)

El especialista `Frontend Developer` (traza `53d0722b56574b2fbb6e7e3cbc4892f9`)
implementó la fuente única de verdad:

**`packages/shared/src/errores/codigos.ts`** — nueva constante centralizada:

```ts
// Códigos que significan "la sesión/token ya no es válido": usados por el
// interceptor de errores y por el servicio de sesión (fuente única de verdad).
export const CODIGOS_TOKEN_RECHAZADO: readonly string[] = [
  CodigoError.AUTH_TOKEN_EXPIRADO,
  CodigoError.AUTH_TOKEN_INVALIDO,
] as const;

export type CodigoTokenRechazado = (typeof CODIGOS_TOKEN_RECHAZADO)[number];
```

Se exporta automáticamente a través de `packages/shared/src/errores/index.ts` →
`index.ts`, por lo que queda disponible como `@mutual-metrics/shared`.

**Consumo en los dos frontends** (se eliminan las definiciones locales):

| Archivo | Antes | Después |
|---|---|---|
| `errores.interceptor.ts` | `const CODIGOS_SESION_INVALIDA: string[]` local | `CODIGOS_TOKEN_RECHAZADO` importado de `@mutual-metrics/shared` |
| `sesion.service.ts` | `const CODIGOS_TOKEN_RECHAZADO: string[]` local | `CODIGOS_TOKEN_RECHAZADO` importado de `@mutual-metrics/shared` |

**Verificación de no-duplicación residual:**

```
grep "CODIGOS_SESION_INVALIDA" apps/frontend        → 0 resultados
grep "const CODIGOS_TOKEN_RECHAZADO" apps/frontend  → 0 resultados
```

### Hallazgo en la corrida (defecto de test, no de código)

La primera corrida del frontend falló en **1 test** por un literal mal escrito por el
test-writer: el spec esperaba `'Ocurrio un error inesperado en el cliente'` (sin tilde)
mientras la producción devuelve `'Ocurrió un error inesperado en el cliente'` (con
tilde). Se corrigió el literal del spec para alinearlo con la salida real de producción
(OACI: el defecto era del test, no del refactor).
