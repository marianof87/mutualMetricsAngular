# Cambios — 30/08/2026 — Cobertura de tests en features del frontend

Registro de los cambios de testing del frontend en la rama `test/frontend/cobertura-features`.

## Objetivo

Cerrar el gap de cobertura de la suite de tests unitarios del frontend. Conforme a
`CLAUDE.md §4.5`, los slices deben mantener un mínimo del 80% de cobertura. Varios
features carecían de specs unitarios, lo que dejaba su lógica sin red de protección
y arrastraba la cobertura global por debajo del umbral.

## Alcance y criterio de gobernanza

Por `CLAUDE.md §2`, los features con dueño de slice no se tocan sin pedido explícito.
En esta ocasión el pedido fue explícito, así que se cubrieron con tests los features
con lógica (con dueño y sin él). No se modificó ningún código de implementación: solo
se **agregaron specs** (`*.spec.ts`) junto a cada componente.

## Decisiones técnicas tomadas

1. **Mock de servicios con `useValue` + `vi.fn()`**: para `ContactoService` y
   `OptimizadorFrontendService` se reemplaza el provider con un objeto mock. **No** se
   usa `provideHttpClient()` porque los componentes no inyectan `HttpClient` directo;
   el HTTP queda encapsulado en su service, que es el que se mockea.
2. **Stub de `BaseChartDirective` (ng2-charts) para `cuadratica`**: se usa
   `overrideComponent` + un stub `canvas[baseChart]` para no instanciar `chart.js`
   (jsdom no tiene canvas 2D). Esto permite testear los `computed` sin la librería
   de gráficos.
3. **Los `effect()` no se ejecutan de forma síncrona al crear el componente** en
   TestBed: se invoca `updateChart()` explícitamente en el test en lugar de depender
   del `effect()` del constructor.
4. **`FormGroup` `nonNullable`**: tras `reset()`, los controles vuelven a `''`
   (string vacío), no a `null`.
5. **NG0100 `ExpressionChangedAfterItHasBeenCheckedError`**: se evita mutando el
   estado del componente **antes** del `detectChanges()` (no después), y usando
   fixtures frescos por caso cuando hay `ngModel` two-way binding.
