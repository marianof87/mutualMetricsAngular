# 1.Div PR #26 — División del PR de cobertura en dos PRs

Registro del proceso aplicado para **dividir el PR #26** (`test(frontend): cobertura de
tests unitarios en features`) que superaba el límite de **500 líneas** de `CLAUDE.md §5`,
descomponerlo en dos ramas/PRs independientes y mergearlos a `main`.

---

## 1. Motivo

- El PR #26 acumulaba **+883 líneas** (10 specs de features), superando el límite
  recomendado de `<500 líneas` por PR (`CLAUDE.md §5`).
- Para respetar la regla de PRs chicos/revisables, se dividió el trabajo en **2 ramas
  independientes**, cada una con su propio PR hacia `main`.

---

## 2. Estrategia de desglose

Se separó por **naturaleza de los tests**:

| Grupo | Característica |
|---|---|
| **Lógica / cálculo pesado** | Specs que ejecutan cálculos, formularios reactivos y services mockeados |
| **Render / smoke** | Specs que validan que el componente se instancia y renderiza correctamente |

La clasificación fue pedida explícitamente:

- **Rama 1 — `cobertura-logica`**: `optimizador`, `financiera`, `cuadratica`, `pricing`.
- **Rama 2 — `cobertura-smoke`**: `contacto`, `historial`, `inicio`, `servicios`,
  `sobre-nosotros`, `novedades`.

> **Nota de clasificación:** `contacto.component.spec.ts` (113 líneas) no es smoke puro —
> incluye tests de lógica de formulario. Se incluyó en la rama smoke siguiendo la
> clasificación acordada y quedó documentado en el PR.

## 5. Incidente de copia (y cómo se resolvió)

Durante la creación de la rama de lógica, al copiar los archivos desde la rama original con
`git show <rama>:<ruta> | Set-Content`, PowerShell **perdió los saltos de línea** y fusionó
cada archivo en una sola línea (el contenido quedaba íntegro pero en una línea gigante).

Se revirtió el commit defectuoso (`git reset --soft`) y se recopió usando **`git checkout
<rama> -- <ruta>`**, que copia el **blob exacto** sin pasar por el pipe, preservando el
formato original. Se verificó con `git diff --cached` que el index era idéntico al blob
original. El commit final `96a5db0` registró 870 inserciones reales.

> **Lección:** para copiar archivos de otra rama, usar `git checkout <rama> -- <archivo>`,
> no `git show | Set-Content` (rompe el line-ending en PowerShell).

## 7. Decisión sobre el límite de 500 líneas (PR #27)

El PR #27 quedó en **870 líneas**, aún por encima de 500. Se tomó la **opción 1** (acordada):
**dejarlo como está y justificarlo en el PR**. Razones:

- Los **specs de cálculo puros suman 620 líneas**; `financiera` (21 tests) es
  intrínsecamente denso.
- Los tests de cálculo no se subdividen sin separar features que se agruparon a propósito.
- Los **docs aportan 250 líneas** (se podrían mover a un PR aparte si se quisiera bajar el
  número).

Se agregó la sección **"Nota de tamaño (CLAUDE.md §5 — PR < 500 líneas)"** al body del
PR #27 documentando el exceso.
